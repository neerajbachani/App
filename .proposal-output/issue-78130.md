## Proposal

### Please re-state the problem that we are trying to solve in this issue.
When a user puts a 1:1 DM IOU expense on hold, the Hold educational modal is inconsistent across entry points. Holding from **Reports → Expenses** shows the submitter educational modal with workspace-oriented “submit” copy, while holding from the expense report page skips the modal entirely. The team decided DM IOU expenses should show the Hold educational modal the first time (with copy that says “send” instead of “submit”), consistently everywhere the Hold action is available.

### What is the root cause of that problem?
There are two separate mechanisms that diverge for DM IOU expenses:

**1. Report-page hold actions skip the modal for DMs (regression from PR #75150).**

Before the fix, hold handlers treated DM reports as an explicit bypass and went straight to toggling hold:

The same `|| isChatReportDM` bypass existed in `MoneyRequestHeaderSecondaryActions`. That is why step 5 in the original repro (More → Hold on the expense report) did **not** show the modal.

**2. Search bulk hold shows the submitter modal, but only with workspace copy.**

On **Reports → Expenses**, bulk hold only gated on `areAllTransactionsFromSubmitter`. For a DM IOU, the user is the IOU report owner, so that check is `true` and the submitter modal opens — but `HoldSubmitterEducationalModal` had no DM context and always used “submit” strings:

### What changes do you think we should make in order to solve the problem?
Reintroduce the Hold educational modal for DM IOU expenses everywhere, and render DM-specific copy when the parent chat is a 1:1 DM.

**1. Stop bypassing the modal for DM reports — treat DM IOUs as submitter-education cases.**

Replace the `|| isChatReportDM` early exit with an explicit `shouldShowHoldEducationalModal` flag (same pattern in `useHoldRejectActions`, `MoneyRequestHeaderSecondaryActions`, and Search bulk hold):

**2. Detect DM IOU reports in Search bulk actions and pass context to the modal.**

Add `areAllTransactionsFromDMReports` and include it in the hold gate so DM selections always get submitter education (not the reject-education modal), even if submitter resolution differs:

```js
const areAllTransactionsFromDMReports = useMemo(() => {
    const reports = getReportsFromSearchData(currentSearchResults?.data);

    return (
        selectedTransactionReportIDs.length > 0 &&
        selectedTransactionReportIDs.every((id) => {
            const iouReport = getReportOrDraftReport(id, reports, undefined, undefined, allReports?.[`${ONYXKEYS.COLLECTION.REPORT}${id}`]);
            if (!iouReport?.chatReportID) {
                return false;
            }
            const chatReport = allReports?.[`${ONYXKEYS.COLLECTION.REPORT}${iouReport.chatReportID}`];
            return isDM(chatReport);
        })
    );
}, [selectedTransactionReportIDs, currentSearchResults?.data, allReports]);

// In the Hold bulk action handler:
const shouldShowHoldEducationalModal = areAllTransactionsFromSubmitter || areAllTransactionsFromDMReports;
```

This is the smallest fix that covers every reproduction path:
- **Reports → Expenses → Hold** → submitter modal with DM copy
- **Expense report → More → Hold** → same modal/copy (no DM bypass)
- **IOU transaction thread → Hold** → same modal/copy
- **Workspace expenses** → unchanged “submit” copy; modal still shows only once via `NVP_DISMISSED_HOLD_USE_EXPLANATION`

Blast radius is limited to Hold educational UX; reject-education and workspace hold flows are untouched.

### What alternative solutions did you explore? (Optional)
- **Skip the modal for DM IOU expenses (early proposals on this issue):** Matches the original QA expectation but contradicts the team decision to reintroduce education for DM holds. Rejected.
- **Only fix Search submitter detection (`areAllTransactionsFromIOUReports` skip):** Would still leave the report page silently skipping the modal and would not address wrong copy. Rejected.
- **Change global copy from “submit” to “send”:** Simpler but inaccurate for workspace expenses that go through report submission. Context-specific keys are safer.
- **Fix only `MoneyReportHeader` submitter check (check IOU report instead of chat report):** Partially correct for gating, but still leaves Search showing workspace copy and does not add DM strings. Superseded by the `isDM`-aware approach above.

### What specific scenarios should we cover in automated tests?
- Assert that holding a DM IOU from Reports → Expenses opens `HoldSubmitterEducationalModal` with `isDM={true}` and DM translation keys on first use.
- Assert that holding the same DM IOU from the expense report More menu opens the same DM copy (no DM bypass).
- Assert that holding a workspace expense still uses “submit” copy (`isDM={false}`).
- Assert that after dismissing the modal once (`NVP_DISMISSED_HOLD_USE_EXPLANATION`), subsequent hold actions on both DM and workspace expenses skip the educational modal and proceed directly to hold reason / hold toggle.

## Proposal

### Please re-state the problem that we are trying to solve in this issue.
When deleted expenses are selected on the Spend page with an active grouped search (e.g. `group-by:from status:deleted`), the bulk-action dropdown shows **"Current view"** as a top-level action instead of **"Export"**. The expected menu for deleted selections is **Undelete**, **Export**, and **Duplicate**; the actual menu is **Undelete**, **Current view**, and **Duplicate**. The export action still works when clicked, but the label is wrong.

### What is the root cause of that problem?
The bulk Export button is built in `useSearchBulkActions`. For deleted selections, `exportButtonOption` is inserted into a dedicated deleted-transactions menu alongside Undelete and Duplicate:

So `text` becomes `export.currentView` ("Current view") instead of `common.export` ("Export"). The button keeps the Export icon and `BULK_ACTION_TYPES.EXPORT` value, but the visible label is wrong.

**Why this does not reproduce without grouping:** For non-grouped deleted selections, the `else if (!isGroupedSearch)` branch adds "Basic export" as a second submenu item, so `subMenuItems.length === 2` and the multi-item branch correctly labels the button "Export".

**Why this does not reproduce for non-deleted selections in the same grouped view:** The same single-item collapse can also show "Current view" for other grouped-only-export scenarios, but the bug report is specifically about the deleted-expenses bulk menu where QA expects the sibling actions to read Undelete / **Export** / Duplicate.

**Regression:** The single-item collapse that inherits the child label was introduced in `aa4b6bb560b` ("avoid nested option when menuItems is 1") and refined in `67adbd211cf` ("fix failing test"), which replaced an earlier approach that returned the raw submenu item (breaking the deleted-transactions menu shape).

This is a **label/state issue**, not a missing export capability — the collapsed button still wires `onSelected` to the "Current view" handler correctly.

### What changes do you think we should make in order to solve the problem?
In the single-item collapse branch, keep the top-level Export label as `translate('common.export')` while still wiring the single submenu item's handler and metadata. "Current view" describes the export *target*, not the bulk-action category; help docs describe it as an option *within* the Export menu.

In `src/hooks/useSearchBulkActions.ts` at line 1927, change:

- `text: singleExportSubMenuItem.text,`
+ `text: translate('common.export'),`

All other properties in the collapsed branch (`onSelected`, `description`, icons, etc.) stay unchanged.

This is the smallest correct fix: one line in `src/hooks/useSearchBulkActions.ts`, no changes to export eligibility logic, and it covers **all** paths where a single export submenu item gets collapsed (deleted + grouped, grouped full-group selection, select-all with one export target, etc.). Click behavior, icons, and handlers stay unchanged.

**Blast radius:** Only affects the visible label when the export submenu collapses to one item. Multi-item export menus (arrow + submenu) are untouched. Existing tests that assert the collapsed label is `export.currentView` (e.g. `useSearchBulkActionsExportTest` grouped-search case) should be updated to expect `common.export`.

### What alternative solutions did you explore? (Optional)
- **Only override the label when `allSelectedAreDeleted`:** Fixes the reported bug but leaves the same mislabeling for other grouped searches where only "Current view" is available. Rejected because the root issue is inheriting a submenu item name onto the Export bulk-action button.
- **Add "Basic export" for grouped deleted selections:** Rejected — grouped exports intentionally route basic export through "Current view" (`handleBasicExport` when `isGroupedSearch`), and duplicating it would be confusing.
- **Revert to returning `subMenuItems` directly when length === 1:** Rejected — that was the pre-`67adbd211cf` behavior and broke the deleted-transactions menu by surfacing a Table-icon "Current view" row instead of an Export bulk action.
- **Keep the submenu (never collapse):** Rejected — unnecessary nesting when there is only one export target; the collapse UX is fine, only the inherited label is wrong.

### What specific scenarios should we cover in automated tests?
- When deleted expenses are selected in a grouped search (`groupBy:from`, `status:deleted`), the bulk Export option's top-level `text` is `common.export`, not `export.currentView`.
- Clicking that Export option still invokes the "Current view" / `handleBasicExport` path for grouped exports (export payload is unchanged).
- When the export submenu has multiple items, the top-level button still reads `common.export` and exposes `subMenuItems` (no regression to collapse logic).
- When deleted expenses are selected in a **non-grouped** search, Export still shows a submenu containing both `export.currentView` and `export.basicExport`.

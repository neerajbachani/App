## Proposal

### Please re-state the problem that we are trying to solve in this issue.

When a multi-expense report's audit trail contains many consecutive system entries (submitted, approved, category changes, exports, etc.), each one currently renders as its own full-height row with an avatar and header, burying the actual conversation. Per the finalized mockups we need: chat comments never collapsed; runs of two or more back-to-back system messages collapsed by default into a compact "N actions" summary row; single system messages left uncollapsed; all system messages rendered without an avatar on one muted line that includes the actor name and timestamp (e.g. "Todd Clyde submitted Today at 12:49 PM"); and no timestamp on the collapsed summary row itself.

### What changes do you think we should make in order to solve the problem?

**1. Centralize system-message classification in `ReportActionsUtils`.**

Move `SIMPLE_MESSAGE_ACTION_TYPES` / `isSimpleMessageAction` from `SimpleMessageContent.tsx` and `isApprovalFlowAction` from `ApprovalFlowContent.tsx` into `ReportActionsUtils`, widening signatures to `OnyxInputOrEntry<ReportAction>` with null guards to match siblings. Re-import from the page components.

Add an explicit allow-list predicate — not `!isAddCommentAction(...)`, which would sweep in IOU/report/trip previews, tasks, and actionable whispers that `ActionContentRouter` renders as interactive cards and must stay individually visible:

```ts
const ADDITIONAL_SYSTEM_MESSAGE_ACTION_TYPES = new Set<string>([
    CONST.REPORT.ACTIONS.TYPE.MODIFIED_EXPENSE,
    CONST.REPORT.ACTIONS.TYPE.MOVED,
    CONST.REPORT.ACTIONS.TYPE.RENAMED,
    CONST.REPORT.ACTIONS.TYPE.EXPORTED_TO_INTEGRATION,
    CONST.REPORT.ACTIONS.TYPE.INTEGRATION_SYNC_FAILED,
    CONST.REPORT.ACTIONS.TYPE.COMPANY_CARD_CONNECTION_BROKEN,
    CONST.REPORT.ACTIONS.TYPE.PLAID_BALANCE_FAILURE,
    CONST.REPORT.ACTIONS.TYPE.CREATED_REPORT_FOR_UNAPPROVED_TRANSACTIONS,
    CONST.REPORT.ACTIONS.TYPE.TAKE_CONTROL,
    CONST.REPORT.ACTIONS.TYPE.REROUTE,
    CONST.REPORT.ACTIONS.TYPE.REASSIGN_APPROVER,
    CONST.REPORT.ACTIONS.TYPE.SETTLEMENT_ACCOUNT_LOCKED,
    CONST.REPORT.ACTIONS.TYPE.REMOVED_FROM_APPROVAL_CHAIN,
    CONST.REPORT.ACTIONS.TYPE.REIMBURSED,
    CONST.REPORT.ACTIONS.TYPE.RECEIPT_SCAN_FAILED,
    // card-state, travel-update, delegate-submit, etc. — every muted-text branch in ActionContentRouter
]);

function isSystemMessageReportAction(reportAction: OnyxInputOrEntry<ReportAction>): boolean {
    if (!reportAction?.actionName || isDeletedAction(reportAction)) {
        return false;
    }
    return (
        isApprovalFlowAction(reportAction) ||
        isPolicyChangeLogAction(reportAction) ||
        isMemberChangeAction(reportAction) ||
        isSimpleMessageAction(reportAction) ||
        ADDITIONAL_SYSTEM_MESSAGE_ACTION_TYPES.has(reportAction.actionName)
    );
}
```

Runs containing actions with visible pending/error feedback (`pendingAction === ADD` or `errors`) should not collapse so optimistic/failed state stays actionable.

Thread it through `ReportActionItemFrame` via a new `displayAsSystemMessage` prop (do **not** overload `displayAsGroup` — that flag also drives hover mini-context-menu offset). **3. Derive a presentation array; keep `visibleReportActions` canonical.**

In `MoneyRequestReportActionsList`, keep `visibleReportActions` as the source of truth for read state, pagination, and optimistic events. Derive `displayReportActions` plus a side map:

```ts
function buildSystemMessageDisplayActions(
    actions: ReportAction[],
    expandedRunMemberIDs: Set<string>,
    forceExpandedActionIDs: Set<string>,
): {displayActions: ReportAction[]; runMeta: Map<string, {memberIDs: string[]; isCollapsed: boolean}>}
```

Walk the ordered array, find maximal runs of adjacent `isSystemMessageReportAction` entries (length ≥ 2, no pending/error boundary), and:
- **Collapsed (default):** keep only the run's first array element in `displayActions`; store all member IDs in `runMeta`.
- **Expanded:** include every member in order; the anchor cell renders a `CollapsedSystemMessagesRow` summary above its normal content so the run can be re-collapsed.

Collapsed members are **removed from the array the list renders**, not hidden via `return null` in `renderItem` — FlashList still allocates null cells, causing blank gaps and desyncing scroll/unread/deep-link index math.

Key expansion state by **member** `reportActionID` set (not just the anchor), so a run that grows across a pagination boundary does not unexpectedly re-collapse when its first element changes.

Pass `[unreadMarkerReportActionID, linkedReportActionID]` as `forceExpandedActionIDs` so runs holding the unread marker or a deep-link target always render expanded.

**4. Rebase every index derived from the rendered array.**

Once rows are removed, `indexWithinReportActions` from `renderReportAction` indexes `displayReportActions`, not `visibleReportActions`. Update:

- `hasNextActionMadeBySameActor` / `isConsecutiveChronosAutomaticTimerAction` inside `renderReportAction`.
- Unread-marker index: resolve the marker **ID** from `visibleReportActions`, force-expand its run, then `findIndex` that ID in `displayReportActions` before passing to `useReportUnreadMessageScrollTracking` (today the index comes from the canonical array at L450–460 while the list may render fewer rows).
- `MoneyRequestReportUnifiedList`: pass `displayReportActions` (not `visibleReportActions`) so `linkedActionLocalIndex`, `initialScrollIndex`, and the viewable-index offset at L226–239 all resolve against what is actually on screen.

**5. Render the collapsed summary row and translation copy.**

Add `CollapsedSystemMessagesRow` — a `PressableWithFeedback` with muted `{count} actions` text (per finalized copy: no "were done"), chevron, `accessibilityRole="button"`, and `accessibilityState={{expanded}}`. Add `report.collapsedSystemMessages` to language files with singular/plural forms.

In `renderReportAction`, when `runMeta` marks the anchor as collapsed, render only the summary row. When expanded, render summary + each member through the existing `ReportActionsListItemRenderer` with `displayAsSystemMessage={true}`.

**6. Prevent chat/system boundary grouping.**

Guard `canActionsBeGrouped` so grouping never spans a chat↔system boundary in either direction:

```ts
if (isSystemMessageReportAction(currentAction) !== isSystemMessageReportAction(adjacentAction)) {
    return false;
}
```

Otherwise a chat comment adjacent to a system row can inherit grouped styling and lose its own avatar/name header.

**Behavior matrix (verified against mockup requirements):**

| Sequence | Before | After |
|---|---|---|
| 1 system message | Full row with avatar + header | One muted line: name + action + timestamp, no avatar |
| ≥2 consecutive system messages | N full rows | 1 collapsed "N actions" row; expand to see all members with timestamps |
| Chat messages | Full rows with avatar | Unchanged |
| System → chat → system | 3 full rows | System: compact line; chat: full row; system: compact line (no run) |
| Run with unread marker / deep link | All rows visible | Run auto-expanded |
| Run with pending/error system action | All rows visible | Run not collapsed |

**Scope:** implement on `MoneyRequestReportActionsList` first (the mockup surface). Shared helpers in `ReportActionsUtils` let `ReportActionsList` adopt the same behavior later; that list is descending/inverted, so the run helper must anchor to the first array element (order-agnostic).

**Regression / blast radius:** `ReportActionItemFrame` gains an opt-in third branch only when `displayAsSystemMessage` is passed; Search, Debug, and inbox chat previews are untouched. Canonical Onyx data and visibility selectors are unchanged. The main risk is index misalignment — covered by step 4 and by unit/UI tests below.

### What alternative solutions did you explore? (Optional)

**Forcing `displayAsGroup=true` for all system messages.** Rejected: `ReportActionItemGrouped` renders children only, so actor name and timestamp disappear; the mockup's one-line "Todd Clyde submitted Today at 12:49 PM" requires a dedicated frame.

**Negation classifier (`!isAddCommentAction`).** Rejected: `ActionContentRouter` also routes IOU/report/trip previews, tasks, and actionable whispers before the chat fallback; a negation would strip their avatars and bury interactive content inside collapsed runs.

**Patching `ReportActionItemFrame` to auto-detect system messages.** Rejected: the frame is shared with Search and Debug standalone renders (`displayAsGroup={false}`), which would lose avatars outside the audit trail.

**Returning `null` for non-anchor run members.** Rejected: FlashList still measures those cells, producing blank gaps and breaking unread-marker / deep-link / viewable-index math in `MoneyRequestReportUnifiedList`.

**Collapsing only in the inbox `ReportActionsList`.** Rejected for initial scope: `MoneyRequestReportView` uses `MoneyRequestReportActionsList` for the multi-expense report the mockup shows; fixing the chat list alone would not address the reported surface.

**Collapsing by identical `actionName`.** Rejected: mockups collapse mixed consecutive system activity (submit + approve + category change), not just repeated same-type entries.

### What specific scenarios should we cover in automated tests?

- `isSystemMessageReportAction` returns true for approval-flow, policy/member change, modified-expense, export/integration/card/plaid, and renamed actions; false for `ADD_COMMENT`, `CREATED`, IOU/report/trip previews, tasks, actionable whispers, and deleted actions.
- `buildSystemMessageDisplayActions`: a lone system message is not grouped; chat messages never grouped; a run of ≥2 groups with correct member IDs; a chat comment splits two runs; `forceExpandedActionIDs` suppresses collapse; pending/error actions block collapse of their run; expansion keyed by member IDs survives anchor shift when pagination extends a run.
- `canActionsBeGrouped` returns false when one action is system and the adjacent is chat (both directions).
- UI: collapsed default for a 3-action run; accessible expand/collapse; expanded members render one-line name + action + timestamp without avatars; chat rows unchanged; unread-marker and deep-linked runs render expanded; Search `ChatListItem` still shows avatars on standalone previews.

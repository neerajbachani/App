## Proposal

### Please re-state the problem that we are trying to solve in this issue.

When an expense report is automatically paid via workspace rules, the server posts a system-generated IOU/PAY message ("automatically paid $X with Expensify via workspace rules"). That action bumps `lastVisibleActionCreated` on the report, but the participant's `lastReadTime` is not advanced. NewDot therefore treats the chat as unread and shows bold/unread indicators in the LHN, even though the user did not perform the payment.

### What is the root cause of that problem?

Unread state is computed purely from timestamps in `isUnread()`. A report is unread when `lastReadTime` is older than `lastVisibleActionCreated` (or `lastMentionedTime`):

function isUnread(report: OnyxEntry<Report>, oneTransactionThreadReport: OnyxEntry<Report>, isReportArchived: boolean | undefined): boolean {
    if (!report) {
        return false;
    }

    if (isEmptyReport(report, isReportArchived)) {
        return false;
    }

    if (!report.lastReadTime) {
        return true;
    }
    // lastVisibleActionCreated and lastReadTime are both datetime strings and can be compared directly
    const lastVisibleActionCreated = getReportLastVisibleActionCreated(report, oneTransactionThreadReport);
    const reportLastReadTime = report.lastReadTime ?? '';
    const threadLastReadTime = oneTransactionThreadReport?.lastReadTime ?? '';
    const lastReadTime = reportLastReadTime > threadLastReadTime ? reportLastReadTime : threadLastReadTime;
    const lastMentionedTime = report.lastMentionedTime ?? '';

    // If the user was mentioned and the comment got deleted the lastMentionedTime will be more recent than the lastVisibleActionCreated
    const isUnreadFromTimestamp = lastReadTime < (lastVisibleActionCreated ?? '') || lastReadTime < lastMentionedTime;

    const drivingActorAccountID =
        (oneTransactionThreadReport?.lastVisibleActionCreated ?? '') > (report?.lastVisibleActionCreated ?? '') ? oneTransactionThreadReport?.lastActorAccountID : report?.lastActorAccountID;

    if (isUnreadFromTimestamp && drivingActorAccountID === deprecatedCurrentUserAccountID && !(lastReadTime < lastMentionedTime)) {
        return false;
    }

    return isUnreadFromTimestamp;
}

**Why one contributor couldn't reproduce:** the non-repro path likely had `lastActorAccountID` resolve to the current user (so the existing self-actor suppression fired), whereas the reporter's push payload resolves the actor to the automation account. The `automaticAction` flag on the hydrated report action is the reliable client-side discriminator regardless of how the backend sets summary fields.

### What changes do you think we should make in order to solve the problem?

Extend `isUnread()` with a second suppression path — parallel to the existing self-actor check — that returns `false` when the driving visible action has `originalMessage.automaticAction === true` and the current user is not the actor. This fixes every caller at once (LHN bold, Unread tab, unread badge counter, mark-all-as-read, search bolding) without patching each site individually.

`ReportUtils` already subscribes to `ONYXKEYS.COLLECTION.REPORT_ACTIONS` via `allReportActions`, so `isUnread` can resolve the driving action with the existing `getLastVisibleActionIncludingTransactionThread` helper (same parent-vs-thread selection logic already used for `drivingActorAccountID`). Preserve the mention exception: if `lastReadTime < lastMentionedTime`, still treat as unread.

Add a helper in `ReportUtils.ts`:

```
function shouldSuppressUnreadForAutomaticAction(
    report: OnyxEntry<Report>,
    oneTransactionThreadReport: OnyxEntry<Report>,
    isReportArchived: boolean | undefined,
    lastReadTime: string,
    lastMentionedTime: string,
): boolean {
    if (lastReadTime < lastMentionedTime) {
        return false;
    }

    const drivingAction = getLastVisibleActionIncludingTransactionThread(
        report?.reportID,
        canUserPerformWriteActionUtil(report, isReportArchived),
        allReportActions,
        undefined,
        oneTransactionThreadReport?.reportID,
        deprecatedCurrentUserAccountID,
    );

    const {automaticAction} = getOriginalMessage(drivingAction) ?? {};
    if (!automaticAction) {
        return false;
    }

    const actorAccountID = getReportActionActorAccountID(drivingAction, report, oneTransactionThreadReport);
    return actorAccountID !== deprecatedCurrentUserAccountID;
}
```

Then, inside `isUnread()` after the existing self-actor guard:

Also add `getLastVisibleActionIncludingTransactionThread` to the existing `ReportActionsUtils` import in `ReportUtils.ts`.

**Why this is the best fix:** it addresses the root mechanism (timestamp unread with no automatic-action exemption) in the single function every unread surface shares. It reuses the established `automaticAction` signal already set by the backend on auto-pay, auto-approve, and auto-forward actions — not fragile `lastMessageText` matching. It also covers sibling flows (auto-approved/auto-forwarded expense reports) that would hit the same timestamp logic.

**Blast radius / edge cases checked:**
- Manual payments and comments from other users: `automaticAction` is absent/false → unchanged, still unread.
- Actions taken by the current user (manual or automatic): existing self-actor suppression still applies first.
- Mentions inside automatic actions: mention timestamp guard prevents suppression.
- **Cold-start window:** before report actions hydrate, `getLastVisibleActionIncludingTransactionThread` returns `undefined` and the row may briefly appear unread until actions load. A backend fix (below) avoids this entirely; the frontend fix is still correct once actions are present.

### What alternative solutions did you explore? (Optional)

1. **Backend-only fix (cleanest long-term):** when the server creates an auto-pay IOU/PAY action, either skip bumping unread-driving fields for non-acting participants or advance their `lastReadTime` alongside the action. Eliminates the cold-start gap and keeps unread semantics server-authoritative. Requires internal backend access (consistent with the issue's `Internal` label).

2. **Patch only `SidebarUtils.getOptionData`:** would fix LHN bold but leave the global unread counter (`UnreadIndicatorUpdater`), Unread tab (`getIsUnreadReportForInboxTab`), mark-all-as-read, and search bolding wrong — incomplete.

3. **Match `lastMessageText` / `lastActionType === IOU`:** the report summary has no `automaticAction` flag and IOU covers both manual and automatic pays, so string/type matching is brittle and would mis-classify manual payments.

### What specific scenarios should we cover in automated tests?

- Assert `isUnread()` returns `false` when the driving action is an IOU/PAY with `originalMessage.automaticAction: true`, actor is an automation account, and `lastReadTime < lastVisibleActionCreated`.
- Assert `isUnread()` returns `true` for a manual IOU/PAY from another user with the same timestamp relationship (no `automaticAction`).
- Assert `isUnread()` returns `true` when an automatic action mentions the current user (`lastReadTime < lastMentionedTime`).
- Assert `isUnread()` returns `false` when the driving automatic action's actor is the current user (existing self-actor path still works).
- Assert `isUnread()` returns `false` for auto-approved (`APPROVED` + `automaticAction: true`) and auto-forwarded (`FORWARDED` + `automaticAction: true`) driving actions by a non-current-user actor.

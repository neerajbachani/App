## Proposal

### Please re-state the problem that we are trying to solve in this issue.

When a user edits a sent message, clears the edit composer completely, navigates to another report, and then returns, the edit draft should still be empty and stay in edit mode. Instead, the original message text reappears in the composer. This only reproduces on Android native because phone layout routes message edits through the bottom compose box (`ComposerWithSuggestions`) rather than the inline editor used on wide layouts.

This is a timing/state-sync bug, not platform-specific logic. Android regression testing reproduces it reliably because narrow-layout navigation is fast enough to beat the 1-second debounce.

PR [#95471](https://github.com/Expensify/App/pull/95471) introduced `shouldExecuteOnUnmount` specifically for **comment** drafts and deliberately left **report-action** edit drafts on cancel-on-unmount. Save/Cancel first calls `clearAllReportActionDrafts()` and then unmounts the editor; an unconditional unmount flush would re-write the just-cancelled draft back into Onyx and recreate the stale-draft regression that PR fixed.

### What changes do you think we should make in order to solve the problem?

We need two complementary behaviors on the same debounced report-action draft save:

1. **Navigate away while editing** → flush the latest pending draft (including `''`) on unmount.
2. **Save / Cancel / confirmed delete** → cancel the pending debounced write *before* `clearAllReportActionDrafts()` so a stale flush cannot resurrect the draft.

**Step 1 — expose cancel from `useDebouncedSaveDraft`:**

```
function useDebouncedSaveDraftImpl(saveDraftFn: (...args: unknown[]) => void, wait = CONST.TIMING.DRAFT_SAVE_DEBOUNCE_TIME, shouldExecuteOnUnmount = false): UseDebouncedSaveDraftResult {
    const isSavePending = useRef(false);

    const debouncedSaveDraft = useDebounce(
        (...args: unknown[]) => {
            saveDraftFn(...args);
            isSavePending.current = false;
        },
        wait,
        {shouldExecuteOnUnmount},
    );

    const saveDraft = (...args: unknown[]) => {
        isSavePending.current = true;
        debouncedSaveDraft(...args);
    };

    return {
        saveDraft,
        isSavePending,
    };
}
```

- **`ComposerProvider` (narrow layout)**: hold a ref that `ComposerWithSuggestions` registers via an effect (`cancelPendingReportActionDraftSaveRef.current = cancelPendingReportActionDraftSave`), and pass `() => cancelPendingReportActionDraftSaveRef.current()` into `useEditMessage`. This covers **all reproduction paths**: empty clears, partial edits immediately before navigation, narrow and wide edit UIs, and Save/Cancel/delete flows without reintroducing the #95471 stale-draft regression.

### What alternative solutions did you explore? (Optional)

**Only set `shouldExecuteOnUnmount = true` (MelvinBot's proposal).** This fixes the navigation path but is unsafe alone: Save/Cancel call `clearAllReportActionDrafts()` and then unmount the editor; an unmount flush would write the stale in-progress text back into Onyx after the clear, recreating the regression fixed in [#95471](https://github.com/Expensify/App/pull/95471). It also targeted `ReportActionItemMessageEdit`, which is not the Android edit surface.

**Special-case flushing only when the pending draft is `''`.** Rejected because it still drops non-empty edits typed immediately before navigation (e.g., user rewrites the message and switches reports within one second).

**Synchronous `saveReportActionDraft` on every clear-to-empty keystroke.** Rejected as it removes debouncing for a common path and adds unnecessary Onyx writes on every backspace while clearing.

**Rely on `useClearReportActionDraftsOnReportChange`.** That hook clears drafts when the report screen mounts/unmounts, but the product explicitly persists in-progress edit drafts across navigation; the bug is that the latest debounced value never reaches Onyx before the composer unmounts, so the stale entry from edit-entry time wins on return.

### What specific scenarios should we cover in automated tests?

- With fake timers, edit a message on narrow layout, clear to empty, navigate/unmount the composer within 1s, reopen the report, and assert the persisted draft message is `''`.
- With fake timers, edit a message, change text to a new non-empty value, navigate/unmount within 1s, reopen, and assert the latest text — not the original — is restored.
- With fake timers, edit a message, change text, press Save or Cancel within 1s, and assert `REPORT_ACTIONS_DRAFTS` stays cleared (no stale draft re-written after `clearAllReportActionDrafts()`).
- Repeat the navigation and Save/Cancel cases for the wide-layout inline `ReportActionItemMessageEdit` path.
